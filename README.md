# Online Retail Market Analysis and Product Recommendation

**Project area:** Data Mining  
**Technique:** Association Rule Mining  
**Algorithm:** Apriori  
**Application:** Rule-based product recommendations

## Project overview

This project analyses historical online retail transactions to discover products that are frequently purchased together. It uses the Apriori algorithm to identify frequent itemsets, generates association rules, and applies those rules in a simple recommendation function.

The project is intended to demonstrate how transaction data can be transformed into market-basket patterns that may support product bundling, cross-selling, and recommendation decisions.

## Business problem

Online retailers can use transaction history to understand which products tend to occur together in customer orders. Discovering these relationships can help inform cross-selling suggestions and product placement. This project explores those relationships using association rule mining.

## Dataset

The project uses the **Online Retail** dataset from the UCI Machine Learning Repository.

- Dataset page: https://archive.ics.uci.edu/dataset/352/online+retail
- Dataset: Online Retail.xlsx
- The data contains transactions from a UK-based online retailer between 1 December 2010 and 9 December 2011.

## Methods and workflow

1. **Data loading and inspection** – load the Excel data and inspect its structure.
2. **Data cleaning** – remove duplicate and incomplete records; retain positive quantities and unit prices of at least £1, as implemented in the notebook.
3. **Exploratory data analysis** – examine popular products and countries, transaction/customer counts, and sales patterns over time.
4. **Transaction basket construction** – group products by invoice, pivot products into columns, and convert the basket to Boolean values.
5. **Frequent itemset mining** – apply Apriori with `min_support=0.01` and `max_len=3`.
6. **Association rule generation** – generate rules using a minimum confidence threshold of `0.30`.
7. **Recommendation function** – recommend consequent products when all antecedent products are present in a customer's basket. Existing basket items are excluded, and recommendations are ranked by confidence and then lift.
8. **Visualisation** – explore support against confidence (with lift represented by colour), the 15 highest-lift rules, and a directed product-association network.

## Recommendation function

The recommendation function accepts:
- `items`: products already present in a customer's basket;
- `rules`: the association rules generated by Apriori;
- `top_n`: maximum number of recommendations to return.

It checks whether each rule's antecedents are a subset of the customer's basket. If so, it adds unseen consequent products as recommendations. When a product is suggested by multiple rules, the function retains the rule with the strongest confidence/lift pair. The output includes support, confidence, and lift.

Example from the notebook:

```python
customer_basket = ['Hot Water Bottle Keep Calm']
recommendations = recommend_products(customer_basket, rules, top_n=5)
print(recommendations)
```

The recommendations depend on the chosen preprocessing filters and mining thresholds. They are associations in historical transactions, not proof that one product causes another to be purchased.

## Key parameters

| Parameter | Value | Purpose |
|---|---:|---|
| Minimum support | 0.01 | Retain itemsets appearing in at least 1% of transactions |
| Minimum confidence | 0.30 | Retain rules with confidence of at least 30% |
| Maximum itemset length | 3 | Limit frequent itemsets to at most three products |
| Rules displayed in lift chart | 15 | Show the highest-lift rules |
| Rules used in network graph | 25 | Visualise the 25 highest-lift rules |

These are project settings, not universal thresholds. Their suitability depends on the dataset, transaction volume, and business objective.

## Visualisations

The notebook includes:

1. **Support vs. confidence scatter plot** – each point represents an association rule; colour represents lift.
2. **Top 15 product associations by lift** – ranks rules by lift.
3. **Product association network** – uses a directed graph to show antecedent-to-consequent relationships among selected rules.

The network graph stores lift as an edge attribute. In the current notebook, edge width and colour are not mapped to lift, so the displayed edges should not be interpreted as visually weighted.

## Challenge encountered

### High RAM usage during transaction-basket creation

Creating a transaction-by-product matrix initially consumed a large amount of Google Colab RAM because the matrix contained many zero and one values.

The notebook converts the one-hot basket to Boolean values:

```python
basket_sets = (basket > 0).astype(bool)
```

This represents product presence as `True` and absence as `False`, rather than retaining integer 1/0 values. This can reduce memory use compared with integer storage, although it is not the same as sparse matrix encoding.

## Limitations and considerations

- The notebook filters out records with missing values, non-positive quantities, and unit prices below £1. These choices affect the transactions and discovered rules.
- The current basket is built at invoice level, so each invoice is treated as one transaction.
- Association rules indicate co-occurrence patterns; they do not establish causation.
- High lift should be interpreted alongside support and confidence. A high lift rule can still be based on relatively few transactions.
- The recommendation function is a simple rule-based demonstration, not a production recommendation service.
- Results may change if preprocessing choices or thresholds change.
